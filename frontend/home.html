What a review gives you

Three separate answers for every statement, kept apart so that one is never mistaken for another. Each detail below is from the review above.

  • A risk score you can trace

    Each statement is scored from 0 to 100 and placed at LOW, MEDIUM, HIGH or CRITICAL. Every point comes from a named finding, such as a DELETE with no WHERE clause. A batch takes its highest statement score, not a sum or an average.

  • Confidence and evidence, stated plainly

    Confidence (HIGH, LIMITED or LOW) says how well the evidence supports the score; it is not a safety rating. The review lists what was collected and what was not. Execution plans are optimizer estimates, not run time or rows changed.

  • Checks to make before running it

    Findings come with DBA actions: confirm the intended row scope, estimate the affected rows, verify backup or point-in-time recovery, consider batching. Eligible SELECT statements also get query advice.

How a review works

  1. Paste the SQL

    One statement or a batch of up to 16, up to 64 KB.

  2. Run the analysis

    The validator parses and scores each statement. It never executes them.

  3. Read the result

    Risk, findings, confidence and limitations, for each statement and for the batch.

  4. Plan the checks

    Use the DBA actions to decide what to verify before the SQL reaches a real database.
